# Система процедурной генерации и стриминга чанков (Unity)

[Unity](https://unity.com)
[![C#](https://img.shields.io/badge/C%23-.NET%20Standard%202.1-512BD4?logo=csharp)](https://learn.microsoft.com/ru-ru/dotnet/csharp/)

Высокопроизводительная, строго ограниченная по памяти система бесшовного стриминга процедурного мира. Разработана с фокусом на строгий контроль CPU/GC-бюджета, асинхронную генерацию, дельта-кэширование состояний и гарантированную связность маршрутов.

> **Цель проекта:** Демонстрация архитектурных паттернов, оптимизаций "горячих путей" (hot paths) и создания масштабируемых систем для Gameplay/Engine программирования.

---

## Ключевые особенности

- **Асинхронный пайплайн генерации:** Тяжелые вычисления (`PathCarver`, `FillPlacer`) вынесены в фоновые потоки через `Task.Run` с безопасным маршалингом результатов в главный поток через кастомный `MainThreadDispatcher`.
- **Строгий бюджет памяти:** Жесткий лимит активных чанков (`MaxActiveChunks`). При превышении лимита система автоматически выгружает самые дальние чанки, предотвращая OOM.
- **Дельта-кэширование (`ChunkCache` + `ChunkDelta`):** Отслеживает изменения во время игры (собранный лут, разрушенные препятствия). Позволяет мгновенно восстанавливать чанки при возвращении игрока без повторной дорогостоящей генерации.
- **A* Path Carving с гарантией связности:** Алгоритм прокладки путей с настраиваемым фактором отклонения (wander factor) и штрафом за прохождение через центр чанка (center avoidance) для создания органичных, нелинейных маршрутов. Гарантирует связность через fallback на алгоритм Брезенхема.
- **Object Pooling:** Полное исключение вызовов `Instantiate`/`Destroy` во время стриминга. Чанки переиспользуются с полным сбросом состояния.
- **Гистерезис загрузки/выгрузки:** Раздельные пороги дистанции для загрузки и выгрузки чанков + минимальное время жизни (`_minLifetimeFrames`). Полностью предотвращает "трешинг" (быстрое создание/уничтожение) на границах чанков.
- **Zero-Allocation оптимизации:** Ручная реализация бинарной кучи (`MinPriorityQueue`), предварительное выделение буферов, использование `Array.Clear` и `[MethodImpl(MethodImplOptions.AggressiveInlining)]` в критических секциях.

## Архитектура системы

```text
[Игрок] 
   │
   ▼
[ChunkStreamManager] (Main Thread)
   ├── Контролирует лимиты памяти и гистерезис
   ├── Проверяет ChunkCache (мгновенное восстановление)
   └── Отправляет запрос в GenerationPipeline
         │
         ▼
[GenerationPipeline] (Background Thread)
   ├── GridGraph (Mutable state)
   ├── PathCarver (A* + Center Avoidance)
   ├── FillPlacer (Weighted random + Nested spawning)
   └── ChunkAssembler → LayoutData (Immutable DTO)
         │
         ▼
[MainThreadDispatcher] → [ChunkPool] → Инстанцирование в сцене
```
## Технический стек
- Категория: Инструменты и паттерны
- Движок: Unity 6+ (совместимо с URP/HDRP) (На более старых не тестировал. Может быть нестабильно)
- Язык C# 10
- Конкурентность: System.Threading.Tasks, Thread-safe очереди, Main-thread маршалинг
- Структуры данных: Кастомная MinPriorityQueue (O(log N)), HashSet/Dictionary tuning, Struct pooling
- Архитектура: Data-Driven Design (ScriptableObjects), Immutable DTO (LayoutData), Dependency Injection
- Профилирование: Frame-accurate лимиты, throttling запросов, отсутствие аллокаций в Update

## Как запустить:

1) Клонируйте репозиторий
2) Откройте проект в Unity 6+.
3)Откройте сцену Assets/Scenes/Demo.unity.
4) Нажмите Play.
5) Используйте (WASD + мышь) для перемещения. Чанки будут динамически подгружаться и выгружаться.
6) (Опционально) Включите гизмо в DemoSceneSetup, чтобы визуализировать пути, якоря (anchors) и границы чанков в реальном времени.

## Ключевые инженерные решения

1) Детерминированные ID чанков: Генерация Guid на основе координат через MD5 гарантирует, что чанк (5, -2) всегда будет иметь один и тот же ID, что критически важно для корректной работы кэша.
2) Разделение Mutable/Immutable состояний: GridGraph и Cell изменяемы только во время генерации в фоновом потоке. Результат упаковывается в иммутабельный LayoutData (DTO), что делает передачу данных между потоками абсолютно безопасной.
3) Умное заполнение (FillPlacer): Поддерживает вложенную генерацию (например, лут на столе) и уважает флаг IsWalkable, позволяя размещать декорации на зарезервированных клетках пути, но блокируя размещение стен.
